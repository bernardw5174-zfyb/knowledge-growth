# 知识生长

> **从一个真实问题开始，让材料逐步长成自己的判断。**

一个由 AI Agent 协助维护、但始终由人确认判断的本地个人知识工作区。

> **预发布 Beta**：协议、脚本与多种 Agent 运行时已完成探索性验证；公开首版只承诺本仓库中写明的本地文件工作流。不同 Agent 对话风格、链接访问能力和附件暴露方式不同，请先用非敏感材料跑一次自己的环境。

---

## 它解决什么问题

资料越收越多，通常会遇到三个问题：

- 原文、摘要、自己的判断混在一起，回头说不清依据；
- AI 看过材料，却没有留下可审、可改、可复用的过程；
- 还没想清楚，结论和行动已经被自动写死。

知识生长提供的是一套轻量的工作协议：

```text
真实问题 + 一份材料
        ↓
保留工作区内的原始副本（Raw）
        ↓
AI 生成可审阅草稿：事实 / 推断 / 不确定项 / 下一步
        ↓
你明确确认后，才成为正式知识
        ↓
需要时，再提炼框架、记录实践或复盘结果
```

**AI 负责整理与提案；人负责确认、取舍与现实决策。**

---

## 核心原则

1. **领域优先**：资料不按“所有 Raw / 所有笔记”混放；每个真实领域都有自己的 Raw、知识、框架、实战和复盘。
2. **来源可追溯**：正式支持的文件附件使用字节级复制保存到领域内 `00-raw/`；原始材料只进不改。
3. **草稿先行**：Agent 可以写草稿，但不能把草稿自动当成你的正式判断。
4. **事实与推断分开**：材料写了什么、AI 推导了什么、仍缺什么信息，应当能被单独审阅。
5. **框架也要确认**：要求“提炼框架”只会生成候选提案；你确认结构后才进入正式框架区。
6. **本地隐私边界**：持久化内容只引用工作区内的相对路径，不应回显聊天附件绝对路径、本机用户名或临时下载位置。

## 工作区结构

```text
vault/
├── 00-系统/                       # schema、manifest、领域索引
├── <已确认领域>/                   # 例如：学习、房产、健康
│   ├── 00-raw/                    # 原始材料的字节级副本，只进不改
│   ├── 01-知识/
│   │   └── _drafts/               # 等待人工确认的草稿
│   ├── 02-框架/                    # 已确认、可跨问题复用的规则
│   ├── 03-实战/                    # 已确认的判断、行动、验证点
│   └── 04-复盘/                    # 结果、修正与经验
└── _templates/                     # 草稿与手工模式模板
```

领域按真实问题逐个创建，不需要一开始就预建“健康 / 理财 / 学习 / 工作”等空目录。资料增多后，领域可以长出自己的细分，但不要破坏五层含义。

## 30 分钟跑通第一次

### 1. 选择一个真实但不敏感的问题

例如：

> 我想整理“如何为一次工作选择收集并判断公开信息”。

不要用身份证、密码、验证码、未脱敏病历、合同、公司机密或他人隐私来做第一次测试。

### 2. 在 Agent 聊天中上传一份相关文件

向 Agent 发送：

> 我正在处理的问题是：……
>
> 这个问题属于：……领域。
>
> 请先读 AGENTS.md，再处理我上传的附件。
>
> 请不要记录附件绝对路径、用户名或临时下载路径。

### 3. 审阅草稿，只判断三件事

- **事实**：材料里真的这样说了吗？
- **推断**：AI 的关联和解释你认吗？
- **下一步**：这一步对你的真实问题有用、且愿意做吗？

你明确说“确认 / 晋升这份草稿”后，Agent 才能将它放入 `01-知识/` 顶层。

## 框架如何产生

当你已经确认了多份知识，并主动说“提炼成框架”时，Agent 的第一步必须是创建**框架提案**，而不是直接写入 `02-框架/`。

提案至少应说明：

- 推荐的最小充分结构；
- 每一部分究竟解决什么独立问题；
- 输入 → 处理 → 输出（IPO）；
- 适用范围、证据来源、置信度与缺口；
- 哪些内容只是主框架的一节或附件，不应单独建页。

有限城市经验、单个案例或商业文章不能包装成“全国通用规则”。只有你明确确认采用的结构，才会成为正式框架。

## Agent 与运行时边界

本项目提供的是**本地目录契约、写入生命周期和参考脚本**，不是一个统一所有 Agent 人格与能力的应用。

不同 Agent 或模型会自然表现出不同风格：有的先问很多问题，有的简洁执行；有的擅长综合框架，有的更倾向逐项拆分。这不是本协议试图抹平的内容。

协议要求结果守住同一条底线：

| 必须遵守 | 运行时可以不同 |
|---|---|
| Raw → Draft → 人确认 → 正式知识 | 提问数量与回复篇幅 |
| 框架提案 → 人确认 → 正式框架 | 标题、措辞与建议密度 |
| 事实 / 推断 / 不确定项分离 | 链接读取能力与网页访问结果 |
| 不持久化附件绝对路径或用户名 | Agent 的交互界面与授权方式 |

### 文件附件与链接的区别

- **文件附件 / 运行时提供的本地文件路径**：本项目的正式支持路径。Agent 应运行 `scripts/import_attachment.py`，完成字节级复制和校验。
- **URL / 微信文章 / 登录墙网页**：是否能读取取决于运行时与网站限制。本项目**不承诺**任意 URL 都能入库。
- 如果无法取得原始文件字节，Agent 不得把网页摘要或转写内容冒充为严格 Raw；可让用户提供 HTML/PDF/文本文件，或将“二手摘录”显式标为非字节级来源。

详细行为边界见 [`AGENTS.md`](AGENTS.md)、[`vault/00-系统/schema.md`](vault/00-系统/schema.md) 与 [兼容性与验证](docs/兼容性与验证.md)。

## 手工模式

没有可读写本地工作区的 Agent 时，仍可使用：

- [`vault/_templates/手工模式-问题笔记.md`](vault/_templates/手工模式-问题笔记.md)
- [`vault/_templates/知识草稿.md`](vault/_templates/知识草稿.md)
- [`vault/_templates/阶段总结草稿.md`](vault/_templates/阶段总结草稿.md)

手工模式不自动复制 Raw、创建领域或生成草稿，但保留同一套“来源 → 草稿 → 确认 → 复盘”的思路。

## 本地脚本与测试

```bash
# 创建一个已确认领域
python3 scripts/create_domain.py "学习"

# 将运行时明确提供的附件路径做字节级复制
python3 scripts/import_attachment.py "/path/from-runtime/article.md" "学习"

# 运行脚本行为测试
python3 -m unittest discover -s tests -v
```

现有测试覆盖：

- 创建领域时生成完整五层目录并更新索引；
- 同名同字节 Raw 不重复保存；
- 同名不同字节 Raw 不覆盖历史材料；
- 路径型非法领域名被拒绝。

> 这些测试验证的是脚本和目录契约，不能替代某个 Agent 运行时的实际验收。更换 Agent、模型、操作系统或附件方式时，请先使用一份非敏感材料做冒烟测试，并检查所有持久化产物。

## 隐私与安全

- 文件默认保留在你的电脑；但 Agent 是否把材料发送给模型服务商，取决于你选择的运行时、模型与隐私设置。
- 不要上传敏感个人材料、公司机密或他人隐私。
- 不把工作区内的 Raw、草稿、正式知识、实践记录和复盘直接提交到公开仓库；本仓库的 `.gitignore` 默认将这些用户数据排除。
- 本项目不提供医疗、法律、投资、职业或关系决策；它只帮助你保存依据、形成可审阅草稿并记录不确定项。
