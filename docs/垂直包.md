# 垂直包（Vertical Packs）

> 垂直包 = 挂在 `vault/_packages/` 下的**独立 Git 仓库**，提供某一领域的方法论、模板与 Agent skill（如求职包 `job-search-bw`）。本文件定义 Core 侧与垂直包相关的约定。

## 挂载模型（模型 A：只读包 + 私有工作区）

```text
vault/
├── 00-系统/          # Core 结构规则、索引、配置
├── _templates/       # 页模板
├── _packages/        # 公共垂直包挂载区（只读参考区）
│   └── <package_name>/   # git clone 所得；目录名 = repo 名 = manifest.package_name
└── <领域>/           # 用户私有工作区（Core 五层，可写）
```

- **`_packages/` 是只读参考区**：Agent 可引用其中方法，**任何写入不得落在其下**；用户产出一律写 `vault/<领域>/`。
- 两者**不共用目录树**——`git pull` 升级包，永不触碰用户数据。
- 挂载方式：`cd vault/ && mkdir -p _packages && git clone <repo-url> _packages/<package_name>`，然后在 Agent 里说"我要开始<领域>"，Agent 按「已挂载的垂直包」节建工作区。

## 包发现约定

Agent 收到领域任务时：扫描 `_packages/*/manifest.yaml` → 按 `domain` 字段匹配 → 读该包 `skills/` → 产出写 `vault/<领域>/`。**发现靠读 manifest，不靠目录名猜测。** 详见根 `AGENTS.md`「已挂载的垂直包」节。

## 占位约定

- 空目录占位统一用 **`README.md`**（不用 `.gitkeep`）：README 能承载"本目录放什么／由谁写"的说明，对 Agent 有信息量；Core 的 `.gitignore` 白名单法也依赖该文件名。
- 垂直包侧（如 `job-search-bw` 的 `00-raw/`、`01-知识/_drafts/`）同样用 `README.md` 占位。

## 升级

```bash
cd vault/_packages/<package_name>/
git pull
```

用户数据零风险（写入从来不在这个目录树里）。Core 升级时垂直包通常无需改动（接触面只有 `manifest.yaml` 的 `compatible_core_version` 与 README 集成指引）。

## 边界

- 本仓库（Core）**不含** `_packages/`、不含任何领域目录——二者都在用户 vault 中运行时生成。
- 垂直包内容只读；需要修改包内容时，正确动作是复制到自己的工作区再改，或给上游提 issue。
- 案例回流：只有人工脱敏、抽象后的共性规律才可回流公共包（各包自行定义回流机制）。
